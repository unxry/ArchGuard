# Research specification

## Тема

«Разработка гибридного метода автоматизированного контроля соответствия программной архитектуры
исходному коду на основе статического, графового и интеллектуального анализа».

## Объект исследования

Процесс автоматизированного контроля соответствия реализации программной системы заданной
программной архитектуре.

## Предмет исследования

Методы и алгоритмы обнаружения архитектурных нарушений посредством статического анализа исходного
кода, графового анализа зависимостей и интеллектуальной интерпретации программных компонентов.

## Цель

Разработать и экспериментально исследовать гибридный метод автоматизированного контроля
соответствия фактической архитектуры программной системы заданным архитектурным ограничениям
на основе совместного применения статического, графового и интеллектуального анализа.

## Гипотеза

Совместное использование статического анализа исходного кода, топологических характеристик графа
зависимостей и интеллектуального анализа семантического контекста позволяет повысить полноту
обнаружения архитектурных нарушений при сохранении высокой точности по сравнению с применением
отдельных методов анализа.

## Research questions

| RQ | Вопрос |
| --- | --- |
| RQ1 | Какова эффективность статического анализа при выявлении архитектурных нарушений? |
| RQ2 | Какие графовые характеристики наиболее полезны для обнаружения архитектурных аномалий? |
| RQ3 | Какие архитектурные нарушения требуют семантического анализа? |
| RQ4 | Повышает ли Hybrid качество относительно отдельных методов? |
| RQ5 | Снижает ли graph-guided context объём LLM-контекста без снижения качества? |
| RQ6 | Как масштабируется разработанный метод с ростом программной системы? |

## Границы исследования

Основной benchmark: Static / Graph / LLM / Hybrid **только ARCH**. Security не участвует
в Architecture Precision/Recall/F1 и не входит в Hybrid. Java/TypeScript — целевые языки будущих
parsers; IAM language-neutral. Scope — 15 planned ARCH rules в FINDING_CATALOG.md.
Deterministic explicit violations не отменяются LLM, structural signals интерпретируются как
эвристические кандидаты, semantic analysis используется там, где нужны responsibility/context.

Foundation не подтверждает гипотезу и не содержит результатов. Проверка — по
[EXPERIMENT_PROTOCOL](../experiments/EXPERIMENT_PROTOCOL.md); завершение ядра — по
[CORE THESIS COMPLETE](CORE_THESIS_COMPLETE.md).
